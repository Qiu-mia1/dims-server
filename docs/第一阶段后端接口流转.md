## 2. 各 API 详细分析

### 2.1 POST /v1/data-slices — 上传 Bag 文件

#### 功能描述

上传 ROS1 bag 文件，保存到本地文件系统，创建切片元数据和导入任务记录，立即返回 task_id，然后异步执行解析+打标流水线。

#### 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| file | multipart/form-data | MultipartFile | 是 | ROS1 bag 文件（.bag），上限 500MB（由 spring.servlet.multipart.max-file-size 控制） |
| name | multipart/form-data | String | 否 | 切片名称，默认取文件名（不含扩展名） |
| X-Trace-Id | Header | String | 否 | 链路追踪 ID，默认 "auto-generated" |

#### 响应内容

HTTP 202 Accepted
```json
{
  "slice_id": "uuid",
  "task_id": "uuid",
  "status": "UPLOADING"
}
```

#### 数据处理流程

```
Controller: DataSliceController.upload()
  │
  ├─ 验证：MultipartFile 非空（由 Spring 自动处理）
  │
  └─ Service: DataSliceServiceImpl.upload()  [@Transactional]
       │
       ├─ 1. 生成 UUID (sliceId, taskId)
       │
       ├─ 2. 确定切片名称（参数传name → 文件名去扩展名 → "unnamed"）
       │
       ├─ 3. 保存文件
       │     └─ 创建目录 /data/bags/{sliceId}/
       │     └─ file.transferTo(bagPath) → /data/bags/{sliceId}/original.bag
       │
       ├─ 4. 插入 DataSlice 记录 (status=UPLOADING)
       │     ↓ data_slice (WRITE)
       │
       ├─ 5. 插入 IngestionTask 记录 (status=UPLOADING, progress=0)
       │     ↓ ingestion_task (WRITE)
       │
       ├─ 6. 委派异步解析流水线
       │     └─ ingestionPipelineService.processParsePipeline(sliceId, bagPath)
       │           ↑ @Async 异步执行
       │
       └─ 7. 返回 {slice_id, task_id, status: "UPLOADING"}
```

#### 异步解析流水线（IngestionPipelineServiceImpl）

```
@Async 线程池 (core=2, max=4, queue=100)
processParsePipeline(sliceId, bagPath)
  │
  ├─ STEP 1: PARSING ──────────────────────────────────────────────
  │
  │  更新 ingestion_task → status=PARSING, progress=30
  │    ↓ ingestion_task (UPDATE)
  │
  │  调用 Python parse_rosbag.py
  │    └─ PythonExecutor.execute("parse_rosbag.py", {bag_path: ...}, timeout=300s)
  │    └─ 机制：创建临时 JSON 文件 → ProcessBuilder → python3 parse_rosbag.py --input {tmp}
  │    └─ 输出 JSON: {start_ts, end_ts, duration_ms, gps_bbox, msg_count_total, streams[]}
  │
  │  更新 DataSlice 元数据字段
  │    ├─ start_ts, end_ts, duration_ms, msg_count_total
  │    ├─ gps_min_lat, gps_min_lon, gps_max_lat, gps_max_lon
  │    ├─ sensor_types (JSON 数组字符串，由 sensor_category 去重生成)
  │    └─ status = "TAGGING"
  │    ↓ data_slice (UPDATE)
  │
  │  写入 SensorStream 记录（每条 Topic 一行）
  │    └─ 解析 metadata.streams[] → 每个 stream 插入一条 sensor_stream 记录
  │    ↓ sensor_stream (WRITE x N)
  │
  ├─ STEP 2: TAGGING ──────────────────────────────────────────────
  │
  │  更新 ingestion_task → status=TAGGING, progress=70
  │    ↓ ingestion_task (UPDATE)
  │
  │  调用 Python auto_tag.py
  │    └─ PythonExecutor.execute("auto_tag.py", {slice_id, gps_bbox, start_ts, end_ts, sensor_types}, timeout=120s)
  │    └─ 输出 JSON: {tag_ids: ["tag-004", "tag-010"]}
  │
  │  写入匹配的 data_slice_tag 记录
  │    ├─ 验证 tag_id 有效性（tagMapper.exists）
  │    └─ 每条 tag_id 插入一条 data_slice_tag (source="auto")
  │    ↓ data_slice_tag (WRITE x N)
  │
  ├─ STEP 3: READY ────────────────────────────────────────────────
  │
  │  更新 DataSlice → status=READY
  │    ↓ data_slice (UPDATE)
  │  更新 ingestion_task → status=READY, progress=100
  │    ↓ ingestion_task (UPDATE)
  │
  │  发布 Kafka 事件 dims.slice.created.v1（当前为 log 占位）
  │
  └─ ERROR 处理：任一步骤失败
       ├─ data_slice → status=ERROR, error_msg=异常信息
       └─ ingestion_task → status=ERROR, error_msg=异常信息
```

#### 涉及数据库表

| 表 | 操作 | 说明 |
|----|------|------|
| data_slice | R/W | 先 insert（UPLOADING），后 update（TAGGING/READY 元数据） |
| ingestion_task | R/W | 先 insert（UPLOADING），后多次 update（PARSING/TAGGING/READY） |
| sensor_stream | W | 插入 N 条（每个 Topic 一条） |
| data_slice_tag | W | 插入 M 条（每个匹配的 auto-tag 一条） |
| tag | R | 验证 tag_id 有效性 |

#### 数据流转路径

```
  [/data/bags/{sliceId}/original.bag]
  │
  │ 文件保存 (file.transferTo)
  │
  ▼
┌──────────────┐     ┌─────────────────────┐
│  DataSlice    │────▶│  IngestionTask       │
│  (data_slice) │     │  (ingestion_task)    │
└──────┬───────┘     └─────────────────────┘
       │
       │ Python 解析
       ▼
┌──────────────┐     ┌─────────────────────┐
│ parse_rosbag │────▶│  SensorStream × N   │
│ .py          │     │  (sensor_stream)     │
└──────┬───────┘     └─────────────────────┘
       │
       │ Python 打标
       ▼
┌──────────────┐     ┌─────────────────────┐
│ auto_tag.py  │────▶│  DataSliceTag × M   │
│              │     │  (data_slice_tag)    │
└──────────────┘     └─────────────────────┘
       │
       ▼
  Kafka 事件 (dims.slice.created.v1)
```

### 2.2 GET /v1/tasks/{taskId} — 查询导入任务状态

#### 功能描述

查询数据切片导入过程中的异步任务进度。前端可通过轮询此接口实现进度条展示。

#### 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| taskId | Path | UUID | 是 | 导入任务 ID |
| X-Trace-Id | Header | String | 否 | 链路追踪 ID |

#### 响应内容

HTTP 200 OK （直接返回 IngestionTask 实体）
```json
{
  "id": "uuid",
  "slice_id": "uuid",
  "status": "PARSING",
  "progress": 30,
  "error_msg": null,
  "created_at": "2026-07-25T08:30:00Z",
  "updated_at": "2026-07-25T08:30:05Z"
}
```

状态流转：`UPLOADING (0%) → PARSING (30%) → TAGGING (70%) → READY (100%)`，任一步骤失败进入 `ERROR`。

#### 数据处理流程

```
Controller: TaskController.getTask()
  │
  └─ Service: IngestionServiceImpl.getTask()
       │
       ├─ ingestionTaskMapper.selectById(taskId)
       │    ↓ ingestion_task (READ)
       │
       ├─ 如果返回 null → 抛出 TASK_NOT_FOUND
       │
       └─ 返回 IngestionTask 实体
```

#### 涉及数据库表

| 表 | 操作 | 说明 |
|----|------|------|
| ingestion_task | R | 按 taskId 查询一条记录 |

### 2.3 GET /v1/data-slices — 条件检索数据切片列表

#### 功能描述

多条件分页检索数据切片。支持时间范围、传感器类型、标签、GPS 位置、关键字模糊搜索、状态过滤和排序。

#### 请求参数

| 参数 | 位置 | 类型 | 默认值 | 说明 |
|------|------|------|--------|------|
| start_ts | Query | RFC3339 | - | 数据起始时间（含），示例 "2026-07-24T09:00:00Z" |
| end_ts | Query | RFC3339 | - | 数据结束时间（含） |
| sensor_types | Query | String | - | 逗号分隔，如 "camera,lidar,radar"，多值 AND 逻辑 |
| tags | Query | String | - | 逗号分隔的标签 **ID**，须全部匹配（AND 逻辑） |
| lat | Query | Double | - | 中心纬度（WGS84），须配合 lon + radius 使用 |
| lon | Query | Double | - | 中心经度（WGS84） |
| radius | Query | Integer | - | 搜索半径，单位：米 |
| keyword | Query | String | - | 文件名/备注模糊搜索（LIKE %keyword%） |
| status | Query | String | - | 切片状态过滤：READY / ERROR |
| page | Query | Integer | 1 | 页码，从 1 开始 |
| page_size | Query | Integer | 50 | 每页条数，最大 500 |
| sort | Query | String | "created_at:desc" | 排序表达式，格式 "field:direction" |
| X-Trace-Id | Header | String | "auto-generated" | 链路追踪 ID |

#### 响应内容

HTTP 200 OK
```json
{
  "items": [
    {
      "id": "uuid",
      "name": "上海外环_采集车01",
      "file_size": 212512478,
      "duration_ms": 600000,
      "start_ts": "2026-07-24T10:00:00Z",
      "end_ts": "2026-07-24T10:10:00Z",
      "gps_bbox": { "min_lat": 31.20, "min_lon": 121.40, "max_lat": 31.25, "max_lon": 121.50 },
      "sensor_types": ["camera", "lidar"],
      "msg_count_total": 16217,
      "tags": ["highway", "daytime"],
      "status": "READY",
      "download_url": "/v1/data-slices/{id}/exports",
      "created_at": "2026-07-25T08:30:00Z"
    }
  ],
  "total": 42,
  "page": 1,
  "page_size": 50
}
```

#### 数据处理流程

```
Controller: DataSliceController.search()
  │
  ├─ 接收所有参数为 @RequestParam Map<String, String>
  ├─ 过滤空值（key: value 形式）
  ├─ ObjectMapper.convertValue → SliceSearchRequest (snake_case → camelCase)
  │
  └─ Service: DataSliceServiceImpl.search()
       │
       ├─ [C-3] RFC3339 → MySQL 兼容格式转换
       │     OffsetDateTime.parse → LocalDateTime → "yyyy-MM-dd HH:mm:ss"
       │
       ├─ [C-4] GPS 中心点 + 半径 → 包围盒
       │     latDelta = radius / 111320.0
       │     lonDelta = radius / (111320.0 * cos(lat))
       │     → minLat, maxLat, minLon, maxLon
       │
       ├─ [C-5] 排序参数白名单校验
       │     validateSort("created_at:desc")
       │     → 允许列: created_at, start_ts, end_ts, file_size, name
       │     → 允许方向: ASC, DESC
       │     → 防止 SQL 注入
       │
       ├─ dataSliceMapper.searchSlices(request)
       │    ↓ DataSliceMapper.xml 动态 SQL
       │    │
       │    ├─ status: 精确匹配 WHERE status = ?
       │    ├─ start_ts: WHERE start_ts >= ?
       │    ├─ end_ts: WHERE end_ts <= ?
       │    ├─ sensor_types: JSON_CONTAINS(sensor_types, '"camera"') AND JSON_CONTAINS(...)
       │    ├─ keyword: WHERE name LIKE CONCAT('%', ?, '%')
       │    ├─ tags: 子查询
       │    │   SELECT dst.slice_id FROM data_slice_tag dst
       │    │   WHERE dst.tag_id IN (?,?,?)
       │    │   GROUP BY dst.slice_id HAVING COUNT(DISTINCT dst.tag_id) = ?
       │    ├─ GPS: 包围盒重叠检测
       │    │   gps_min_lat <= ? AND gps_max_lat >= ?
       │    │   gps_min_lon <= ? AND gps_max_lon >= ?
       │    └─ ORDER BY ${sort}（白名单确认后直接拼接）
       │
       ├─ 转换 Entity → SliceItem（每条都单独查询标签）
       │     └─ dataSliceTagMapper.selectTagsBySliceId(sliceId)
       │          ↓ data_slice_tag INNER JOIN tag (READ)
       │
       ├─ 估算总数（按 status 粗略计数）
       │     └─ dataSliceMapper.selectCount(LambdaQueryWrapper)
       │
       └─ 组装 SliceListResponse
```

#### 涉及数据库表

| 表 | 操作 | 说明 |
|----|------|------|
| data_slice | R | 多条件动态检索 + COUNT |
| data_slice_tag | R | 每个切片项需关联查询标签（N+1 问题） |
| tag | R | 通过 JOIN 获取标签名 |

### 2.4 GET /v1/data-slices/{sliceId} — 获取切片详情

#### 功能描述

获取单个数据切片的完整信息，包括基本信息、提取的传感器流（SensorStream）列表、关联的标签列表。

#### 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sliceId | Path | UUID | 是 | 切片 ID |
| X-Trace-Id | Header | String | 否 | 链路追踪 ID |

#### 响应内容

HTTP 200 OK （SliceDetailResponse，含 DataSlice 全部字段 + streams 列表 + tags 列表）

#### 数据处理流程

```
Controller: DataSliceController.getDetail()
  │
  └─ Service: DataSliceServiceImpl.getDetail()
       │
       ├─ 1. dataSliceMapper.selectById(sliceId)
       │    ↓ data_slice (READ)
       │    └─ 如果 null → 抛出 SLICE_NOT_FOUND
       │
       ├─ 2. sensorStreamMapper.selectBySliceId(sliceId)
       │    ↓ sensor_stream (READ)
       │    └─ SQL: SELECT ... FROM sensor_stream WHERE slice_id = ? ORDER BY topic ASC
       │
       ├─ 3. dataSliceTagMapper.selectTagsBySliceId(sliceId)
       │    ↓ data_slice_tag INNER JOIN tag (READ)
       │    └─ SQL: SELECT t.* FROM data_slice_tag dst INNER JOIN tag t ON dst.tag_id = t.id WHERE dst.slice_id = ?
       │
       └─ 4. 转换为 SliceDetailResponse
            ├─ entity → GpsBbox 对象组装（4 个独立字段→嵌套对象）
            ├─ sensor_types JSON 字符串 → List<String>
            ├─ tag 列表 → tag 名称列表
            └─ StreamInfo 转换（LocalDateTime → RFC3339）
```

#### 涉及数据库表

| 表 | 操作 | 说明 |
|----|------|------|
| data_slice | R | 按 sliceId 查询 |
| sensor_stream | R | 按 slice_id 查询所有关联流 |
| data_slice_tag | R | 关联查询 |
| tag | R | JOIN 查询标签详情 |

### 2.6 POST /v1/data-slices/{sliceId}/exports — 创建导出任务

#### 功能描述

按时间窗口和 Topic 列表裁剪 bag 文件。相同参数可复用已有导出产物（24 小时内有效）。创建后异步执行 Python 裁剪脚本。

#### 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sliceId | Path | UUID | 是 | 切片 ID |
| X-Trace-Id | Header | String | 否 | 链路追踪 ID |

请求体（JSON）：
```json
{
  "start_ts": "2026-07-24T10:05:00Z",
  "end_ts": "2026-07-24T10:05:30Z",
  "topics": ["/sensor/camera_front_wide/video", "/sensor/imu"],
  "format": "bag"
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| start_ts | 是 | 导出时间窗口起点，UTC RFC3339 |
| end_ts | 是 | 导出时间窗口终点，UTC RFC3339 |
| topics | 否 | 导出的 Topic 列表，空=全部 |
| format | 否 | 导出格式，默认 "bag"，Phase 1 仅支持 bag |

#### 响应内容

HTTP 202 Accepted
```json
{
  "export_id": "uuid",
  "slice_id": "uuid",
  "status": "PENDING",
  "format": "bag",
  "file_size": null,
  "download_url": null,
  "expires_at": "2026-07-27T08:30:00Z",
  "created_at": "2026-07-26T08:30:00Z"
}
```

#### 数据处理流程

```
Controller: ExportController.createExport()
  │
  └─ Service: ExportServiceImpl.createExport()  [@Transactional]
       │
       ├─ 1. 验证切片存在且为 READY 状态
       │    └─ dataSliceMapper.selectById(sliceId)
       │    ↓ data_slice (READ)
       │    └─ status != "READY" → 抛出 INVALID_SLICE_STATUS
       │
       ├─ 2. 检查缓存复用
       │    └─ findExistingValidExport(sliceId, request)
       │    └─ 查询 export_task WHERE slice_id=? AND status="READY" AND format=? AND expires_at > now
       │    ↓ export_task (READ)
       │    └─ 逐一对比 start_ts, end_ts, topics 是否完全一致
       │    └─ 如果找到 → 直接返回现有任务的 ExportResponse（缓存命中）
       │
       ├─ 3. 创建 ExportTask 记录
       │    ├─ 生成 exportId (UUID)
       │    ├─ status = "PENDING"
       │    ├─ expires_at = now + 24h
       │    └─ exportTaskMapper.insert(task)
       │    ↓ export_task (WRITE)
       │
       ├─ 4. 触发异步导出流水线
       │    └─ exportPipelineService.processExportPipeline(task, bagFilePath, request)
       │         ↑ @Async 异步执行，传入完整 task 对象避免事务未提交竞态
       │
       └─ 5. 返回 ExportResponse
```

#### 异步导出流水线（ExportPipelineServiceImpl）

```
@Async 线程池
processExportPipeline(task, bagFilePath, request)
  │
  ├─ 更新 export_task → status=PROCESSING
  │    ↓ export_task (UPDATE)
  │
  ├─ 调用 Python extract_export.py
  │    └─ PythonExecutor.execute("extract_export.py", {
  │         bag_path, output_path, start_ts, end_ts, topics, format
  │       }, timeout=600s)
  │    └─ 输出路径: /data/exports/{sliceId}/{exportId}/output.bag
  │    └─ 输出 JSON: {success, output_path, file_size, msg_count}
  │
  ├─ 成功 →
  │    ├─ export_task.status = "READY"
  │    ├─ export_task.file_path = outputPath
  │    ├─ export_task.file_size = result.file_size
```

## 4. Kafka 事件发布现状

### 当前实现

| 事件 Topic | 触发时机 | 代码位置 | 实际发布方式 |
|------------|----------|----------|-------------|
| dims.slice.created.v1 | 解析+打标完成，状态变更为 READY | IngestionPipelineServiceImpl (行 190-195) | **日志占位**，仅 log.info，未调用 SliceEventPublisher |
| dims.slice.deleted.v1 | 切片删除完成 | DataSliceServiceImpl (行 260-262) | **日志占位**，仅 log.info，未调用 SliceEventPublisher |

### SliceEventPublisher 组件

已定义完整的 Kafka 事件发布器（`SliceEventPublisher.java`），包含：
- `publishSliceCreated(SliceCreatedEvent)` — 发送 `dims.slice.created.v1`
- `publishSliceDeleted(SliceDeletedEvent)` — 发送 `dims.slice.deleted.v1`
- Kafka 不可用时降级为日志警告（`@Autowired(required=false)` + `isKafkaAvailable()` 检查）

但当前**流水线代码未调用**该发布器，而是使用 log.info 作为占位。Kafka 事件在 Phase 1 为「日志埋点」状态，后续接入真实 Kafka 后接入即可。

### Kafka 配置

- KafkaConfig 使用 `@ConditionalOnProperty(name = "spring.kafka.bootstrap-servers")`，仅当配置存在时生效
- 本地开发环境无 Kafka 也能正常启动
- 序列化：key=StringSerializer, value=JsonSerializer
- Producer 配置：acks=1, retries=3, batch.size=16384

### 关键设计要点

1. **异步解耦**：导入和导出都采用 `@Async` + 独立 Pipeline Bean 的模式，确保同步 API 快速返回 `202 Accepted` / `task_id`

2. **Pipeline 独立 Bean**：`IngestionPipelineService` 和 `ExportPipelineService` 设计为独立 Bean，确保 `@Async` 通过 Spring AOP 代理正常生效（避免从同一类内部调用时 AOP 失效）

3. **Python 调用隔离**：PythonExecutor 通过临时 JSON 文件 + ProcessBuilder 调用，输入输出均为 JSON，便于调试和替换

4. **缓存复用**：导出任务通过 `(sliceId, start_ts, end_ts, topics, format)` 五元组匹配，有效期内（24h）的 READY 任务可复用

5. **事务边界**：上传和创建导出使用 `@Transactional`，异步 Pipeline 在事务提交后执行，通过传入对象而非 ID 避免竞态条件

6. **安全设计**：排序参数通过白名单校验防止 SQL 注入；GPS 包围盒计算在 Service 层而非 SQL 层；状态过滤限制值域

7. **Kafka 降级**：KafkaConfig 使用 `@ConditionalOnProperty`，无 Kafka 配置时 Producer Bean 不创建，`SliceEventPublisher` 降级为日志警告，不影响主流程
